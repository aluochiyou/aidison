# 总规划与技术选型

## 1. 最终主线

当前主线不是接入某个完整开源产品，也不是把多个项目拼成微服务集合，而是：

```text
可修改的 Deep Agents Core / LangGraph 执行层
+ Aidison 自有 FastAPI 控制面
+ Aidison 自有 PostgreSQL Domain 与 durable runtime
+ deep-agents-ui 派生的 Project-first Next.js 控制台
+ 官方 MCP/SDK 的薄适配器
```

最终只允许存在一棵 Aidison 产品代码树、一个 canonical Domain、一个 Job/Attempt/Delegation/JoinReceipt 事实源和一套对外 API。

## 2. 主要技术选型

| 层 | 选型 | 选择理由 | Aidison 自有边界 |
|---|---|---|---|
| Agent harness | Deep Agents Core 0.7.1 + LangGraph | 提供 graph、middleware、tool、filesystem、structured output 和 subagent 执行骨架；源码可读可改 | Domain、durable child、预算、结果接纳不交给上游 |
| API 控制面 | FastAPI + Pydantic | Python Agent 生态一致，typed API，适合个人项目 | command、basis、ETag、幂等、snapshot 和 SSE |
| 数据库 | PostgreSQL 17 + SQLAlchemy async + Alembic | 同时承担业务事实、运行时、预算和事件，避免引入第二状态系统 | schema、不变量、事务和迁移 |
| 前端 | Next.js 16 + React 19 + SWR + Radix primitives | 继承 deep-agents-ui 的成熟渲染能力，同时可改成 Project-first | 产品信息架构、审批、模块/证据/版本投影 |
| 全网搜索 | Tavily Remote MCP | 复用官方维护的 search 能力，不自建搜索引擎 | allowlist、预算、结果上限和 Evidence 链 |
| 已知 URL | HTTPX + Trafilatura | Aidison 必须持有原始字节、hash、SSRF/redirect/MIME/size 安全边界 | 安全下载、正文抽取、Artifact |
| GitHub | GitHub MCP Server v1.8.0，stdio | 复用官方 repository/code/content 协议，不自写 REST/Search API | 精确三工具、只读校验、预算和 Artifact |
| 模型 | OpenAI-compatible gateway；百炼优先，OpenAI 预留 | 保持 provider-neutral contract | 模型路由、缺 Key fail closed、usage 账本 |
| Artifact | 本地/Docker content-addressed volume | 适合单机、可审计、恢复简单 | hash、metadata、lineage、状态 |
| 可观测 | PostgreSQL 运行事件和预算为主 | 核心状态可自证，不依赖外部 tracing 平台 | LangSmith/Langfuse 只允许可丢弃投影 |

## 3. 上游源码采用方式

### Deep Agents Core

- 上游：`langchain-ai/deepagents`
- 固定 commit：`0d38eb2df39b0652d6f2ad92e8d14ae5edc78398`
- 上游版本：`deepagents==0.7.1`
- 导入路径：`packages/deepagents`

当前是源码归 Aidison 管理的 vendor 模式，不是不可修改 SDK。后续是否退出 vendor 是独立决策，详见未完成项。

## 4. 为什么没有把 DeerFlow、MARS、LIA 或 NextBoard 当主框架

- DeerFlow：完整产品树较强，但会带入第二套领域、控制面和产品结构；项目收敛为个人 Demo 后，整仓魔改成本大于收益。
- MARS：研究工作台外形完整，但核心是固定 workflow/prompt role，耐久性和事实源较弱。
- LIA：产品工程和调试 UI 有价值，但 session/chat/runtime 较重，会与 Aidison 的 Domain 和 Job 语义冲突。
- NextBoard：硬件设计 rubric、需求冻结和评审 Gate 有价值，但本质是 Prompt/Skill/文档协议，不是产品 runtime。
- AgentScope：真实 manager/worker 与 provider/tool 设计有价值，但不是 durable Domain 控制面。
- Dapr Agents：durable workflow 有价值，但 Pre-Alpha 且 Dapr sidecar 对个人项目过重。
- OpenRath：lease/fencing/effect/interrupt 思想最接近，但 v1/v2 双 runtime 不适合直接继承。

## 5. 外部能力采购原则

当前稳定原则是：

1. 标准库可解决时先用标准库。
2. 通用协议和平台能力优先官方 API、SDK、MCP。
3. 可靠成熟的开源实现优先于自写通用基础设施。
4. Aidison 只自有产品不变量、领域规则、安全边界、预算、状态、证据和薄适配层。

因此没有自写 Tavily client、GitHub Search API、MCP transport、crawler、文档微服务或 tracing dashboard。

## 6. Aidison 必须原创保留的部分

现有参考项目都没有同时提供：

- 通用 DIY `RequirementRevision → Module → Decision → SolutionVersion` 语义；
- 从原始外部字节到方案、BOM 和版本的 EvidenceBinding；
- Proposal-only Agent 与用户批准后的 canonical promotion；
- durable child Job、generation fencing、late-result quarantine 和唯一 JoinReceipt；
- provider/tool 模糊结果下的 reserve/dispatched/settled/ambiguous 预算语义；
- Observation → 传递影响闭包 → PatchSet → 局部复用新版本；
- 同一控制台对阶段、模块、证据、预算、运行尝试和版本因果的投影。

这些能力才是项目面试展示时应重点说明的个人工程贡献。

## 7. 明确延期的技术

| 技术/能力 | 当前结论 | 重新评估条件 |
|---|---|---|
| Redis/Celery | 不采用 | PostgreSQL worker 吞吐或锁竞争有实测瓶颈 |
| 向量库/图数据库 | 不采用 | FTS/结构化引用在真实 fixture 上召回不足，消融证明收益 |
| Dapr/Kubernetes | 不采用 | 单机边界被明确取消，且运维需求真实出现 |
| Langfuse 自托管 | 不采用 | 有持续 tracing 需求并接受额外 ClickHouse/Redis/对象存储成本 |
| LangSmith | 可选、默认关闭 | 用户需要轻量 LLM trace 且完成脱敏策略 |
| React Flow | 延期 | 模块依赖/影响图成为真实交互验收项 |
| A2A | 延期 | 必须连接独立部署且不透明的外部 Agent |
| 自动购物 | 延期 | 官方交易 API、沙箱、审批、对账和幂等全部可验证 |
