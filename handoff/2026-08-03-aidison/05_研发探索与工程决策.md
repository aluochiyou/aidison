# 研发探索与工程决策

本文件记录可审查的工程取舍、证据和失效条件，不记录聊天流水或隐藏推理。

## 1. 从“大而完整”转向“个人面试 Demo”

早期研究同时考虑 DeerFlow 等完整产品树、多个 runtime、购物、A2A、可观测和高级控制台，工程量超出个人项目边界。最终把目标收敛为一个可解释的通用 DIY 闭环，首个 pilot 为四旋翼，突出四个面试亮点：

1. 证据绑定的工程方案；
2. 有 lease/fencing/receipt 的耐久多 Agent；
3. 不可变 SolutionVersion 与局部影响修订；
4. Project-first 可交互控制台。

自动购物、A2A、动态 swarm、完整观测平台和物理控制因此延期。

## 2. 不采用单一完整开源产品作为 Aidison

比较过 DeerFlow 完整产品树、AgentScope/Deep Agents 执行 adapter、OpenRath/Dapr durable substrate、LIA/MARS/Heph 产品和 UI，以及原生 LangGraph + FastAPI + Next.js。

最终选择以 Deep Agents Core 为可修改执行骨架，Aidison 自建薄但严格的控制面和领域层。原因是没有项目同时满足通用 DIY Domain、版本化事实、durable multi-agent、Evidence/BOM/Verification、浏览器控制台和个人工程量。整仓继承会引入第二事实源或第二调度器。

失效条件：如果 Deep Agents 后续无法维持 typed output、工具约束、Windows 行为或适配成本显著高于原生 LangGraph，可退回更薄的 LangGraph harness；Domain/runtime 不随之更换。

## 3. 单一 runtime 与 durable delegation

LangGraph/Deep Agents 负责单 work-item 内执行，PostgreSQL Job runtime 负责持久身份、lease、generation、取消、重试、迟到结果和唯一接纳。

拒绝 Deep Agents AsyncTask 直接作为 durable ledger、Celery/Dapr/第二 Agent runtime、纯 `asyncio.gather()` 多角色，以及只换 Prompt 就称为多智能体。四个 crash/reclaim 窗口、fan-out replay、JoinReceipt 和 stale generation 测试已通过。

## 4. PostgreSQL 作为唯一业务和运行事实源

Domain、runtime、Profile、budget 和 project events 均进入 PostgreSQL；Artifact bytes 进入 content-addressed volume。LangGraph checkpoint、消息历史、Redis、向量库、文件系统目录或 tracing 平台都不能成为业务真相。

个人项目中，一套可事务化、可迁移、可备份的数据库比多种中间件更易解释和恢复。性能不足必须先由实测证明，不能靠“企业架构”想象。

## 5. 七层记忆不是七套存储

Working、Episodic、Canonical、Evidence、Preference、Procedural、Artifact 是语义所有权，而不是七个数据库。它解决的是“什么可以被记住、谁能写、何时失效”。V0 优先 exact ref、结构化 query 和 PostgreSQL FTS；向量/图索引只在消融证明收益后加入。

## 6. 搜索能力收敛到成熟组件

早期经历 Brave、自写 HTML parser 和 Tavily SDK 候选。能力复用审计后冻结为：

```text
全网 discovery：Tavily Remote MCP
正式网页证据：HTTPX + Trafilatura
GitHub：官方 GitHub MCP
本地源码：rg / rg --files
```

Aidison 仍保留 SSRF、redirect、MIME、size、timeout、预算、Artifact/hash、EvidenceBinding 和 canonical write。因此既不重复实现搜索引擎、crawler、GitHub REST client 或 MCP transport，也没有放弃产品安全和证据价值。

## 7. GitHub MCP 的最小权限设计

固定 v1.8.0，仅开放 repository search、code search、file content 三项只读工具；客户端再次校验工具集合和 `readOnlyHint`。Server 的 read-only 模式不能代替客户端 allowlist。Key 只存在于 worker 子进程，工具返回先进入 Artifact，Agent 不直接获得无界原始结果。

## 8. Vendor Deep Agents 暂时保留

Aidison 使用官方 `HarnessProfile` 后，过去两个主要源码差异已经大部分进入上游；完整 vendor 带来维护成本。但 Windows ripgrep 等价尚未验证，删除目录也属于破坏性结构变化，因此当前不删除 `packages/deepagents`。

未来可以固定上游 SHA 直接依赖；若上游不能覆盖差异，则维护最小 patch/fork；确需深改时仍可以完整 fork。

## 9. Project-first 控制台而不是 Chat-first UI

页面围绕 Project、Requirement、Module、Evidence、Decision、Solution、Impact、Budget 和 Event 展开，而不是把聊天消息、thread/run 或 chain-of-thought 当作主要信息架构。

现有控制台已展示闭环，但模块 drill-down 和 URL 状态化 Module Lens 尚未实现。未来真实需要依赖图时才考虑 React Flow。

## 10. 可观测性选择

以项目事件、Attempt、预算 operation 和固定错误码作为可恢复事实；LangSmith 可作为默认关闭的轻量 trace，Langfuse 自托管延期。Langfuse 自托管会引入 ClickHouse、Redis、对象存储和额外 PostgreSQL，不适合个人 V0。任何 trace 都不能成为业务事实源。

## 11. 购物、A2A 和物理副作用

当前只冻结 effect/approval/idempotency 边界，不实现真实交易、公共 A2A 或设备控制。未来必须保持商品发现与支付分离、cart preparation 与 place order 分离、每个高风险动作独立批准，并记录 prepared/dispatched/succeeded/ambiguous。

A2A 只用于独立系统互操作，不替代内部 delegation；物理装配与飞行目前由用户执行和反馈。

## 12. 参考项目的实际贡献

- Deep Agents：执行 harness、middleware、tool/filesystem 和 subagent。
- OpenRath：lease、fencing、effect ledger、interrupt、cursor SSE 思想。
- AgentScope：事件循环、provider/tool/permission/HITL 思想。
- LIA：SSE、debug/trace UI、工具 manifest 和工程测试组织。
- Heph/NextBoard：硬件兼容、制造 Artifact、需求冻结和 reviewer rubric。
- DeepResearch：计划、并行检索、证据判断和反思 workflow。
- MARS：context manifest、artifact/evaluation shell，同时也是非 durable 多角色反例。
- Dapr Agents：durable child workflow 对照，但未进入 V0。
