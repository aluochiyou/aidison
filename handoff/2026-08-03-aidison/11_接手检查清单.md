# 接手检查清单

## 1. 第一次打开项目

- [ ] 阅读本目录 `README.md`、项目总览和 Git 现场。
- [ ] 阅读根目录 `CONTEXT.md` 和 `UPSTREAM_MAP.md`。
- [ ] 阅读 `docs/ARCHITECTURE.md`、`docs/STATUS.md` 和两个 accepted ADR。
- [ ] 执行 `git status --short`，确认未提交变化仍存在。
- [ ] 执行 `git worktree list`，确认没有意外 Worktree。
- [ ] 执行 `docker compose ps`，记录是否仍有运行服务。
- [ ] 不输出任何环境变量值。

## 2. 只读理解代码

- [ ] 从 `src/aidison/domain/models.py` 理解业务实体。
- [ ] 从 `src/aidison/application/service.py` 理解 canonical command。
- [ ] 从 `src/aidison/application/research.py` 理解 durable parent/child/Join。
- [ ] 从 `src/aidison/infrastructure/runtime.py` 理解 lease/fencing/replay。
- [ ] 从 `src/aidison/infrastructure/budget.py` 理解预算状态机。
- [ ] 从 `src/aidison/tools/web_search.py` 和 `github.py` 理解外部能力边界。
- [ ] 从 `src/aidison/api/app.py` 理解 API 和 snapshot/SSE。
- [ ] 从 `web/src/app/components/ProjectConsole.tsx` 理解当前控制台。

## 3. 恢复开发前的安全门

- [ ] 用户明确授权恢复开发。
- [ ] 先备份当前 dirty worktree 或形成可审查 Git 封存点。
- [ ] 不把测试指向 `localhost:5432/aidison`。
- [ ] 使用全新临时 PostgreSQL 运行 non-live 测试。
- [ ] 运行 Ruff、strict mypy、Alembic drift、frontend lint/build。
- [ ] 任何 live 测试都保持有界预算，不盲目重试。
- [ ] 不删除 vendor、历史 Artifact、数据库记录、branch 或 volume，除非用户批准。

## 4. 建议的恢复顺序

1. 先解决 Git 封存，而不是继续加功能。
2. 再决定运行库 5 条 Artifact 和长期测试库 stale Profile 的处理策略。
3. 选择“稳定 live gate”或“deterministic 面试 fixture”中的一个主目标。
4. 如果需要可见增强，只做 Module Lens，不同时增加新后端 schema。
5. 完成一次项目级验证后，再评估 Deep Agents vendor 退出。
6. V0 封口后才讨论 Shopping、A2A 或 tracing。

## 5. 面试前检查

- [ ] 能用一句话解释 Aidison 的产品价值。
- [ ] 能画出 PostgreSQL Domain、durable runtime、Agent harness、MCP 和前端关系。
- [ ] 能解释 Logical Agent、Subagent、Workflow 和 Tool 的区别。
- [ ] 能展示一个 crash/reclaim 测试和唯一 JoinReceipt。
- [ ] 能展示 EvidenceBinding 和 Artifact hash。
- [ ] 能展示 SolutionVersion V1→V2 的 affected/reused 语义。
- [ ] 能明确说出真实 live gate 尚不稳定，而不是回避失败。
- [ ] 能区分个人原创能力和成熟开源采购能力。

- [ ] `research/` 三套研究目录仍存在。
