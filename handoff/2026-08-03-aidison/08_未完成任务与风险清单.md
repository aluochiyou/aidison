# 未完成任务与风险清单

## 1. 当前停止原则

用户已经决定暂停开发。因此本文件是未来恢复开发时的待办和决策清单，不授权自动继续实现，也不要求为了“完成率”补齐所有能力。

## 2. P0：恢复开发后最先决定的事项

### P0-1 形成可恢复 Git 封存点

- 现状：42 项未提交变化包含多项有效产品实现。
- 风险：误用 reset/clean 会丢失工作；单个大提交又难以审查。
- 所需动作：复核验证后按逻辑批次提交或先建立完整备份。
- 完成证据：提交列表、clean status、tag 或外部备份 hash。

### P0-2 真实 Research live gate 的重复稳定性

- 现状：完整四旋翼闭环曾成功；重复运行出现 child `worker_error`，Docker 内最后一次又遇到瞬时 GitHub DNS 失败。
- 风险：演示时外部 provider/tool 行为不确定。
- 约束：不得增加无界重试、放宽预算、跳过 EvidenceBinding 或把一次成功伪装成稳定。
- 建议：固定 fixture、记录 tool choice、区分 DNS/provider/model contract，并只做一次有界复现。
- 完成证据：相同冻结 Profile 和预算下连续可重复的端到端通过。

### P0-3 运行库 5 条缺字节 Artifact 记录

- 现状：数据库中有 5 条 `present` metadata，volume 无对应 bytes；备份 Gate 正确拒绝。
- 风险：直接改状态或删除记录会改变历史，直接绕过会生成不完整备份。
- 用户决策：保留审计历史并标记 missing、删除测试污染记录，或重建演示库。
- 前置条件：先做完整数据库/volume 快照并核对每条 lineage。

### P0-4 长期测试库 stale Profile

- 现状：`127.0.0.1:55432/aidison_test` 有一条定义不同的 `research-worker-ro@4`。
- 风险：迁移测试会被 immutable gate 拒绝。
- 处理方式：继续使用无卷临时测试库，或经用户确认后重建长期测试库。

## 6. 已知运行和工程风险

| 风险 | 当前缓解 |
|---|---|
| 外部搜索和模型不稳定 | 有界调用、固定错误码、Artifact、预算和 fail closed |
| Git 未提交现场丢失 | 交接清单、禁止 reset/clean；尚需正式封存 |
| 历史 Artifact 不一致 | 备份前只读完整性 Gate |
| 测试误连运行库 | 测试入口拒绝 `5432/aidison` |
| Key 泄露 | Key 只在环境和 worker 子进程；文档不记录值 |
| Vendor 维护成本 | 固定 SHA、UPSTREAM_MAP、完整上游测试；退出决策延期 |
| UI 与 Domain 漂移 | snapshot DTO、server-owned approval、legacy normalization |
| Agent 重试重复副作用 | allocation、operation state、idempotency receipt、fencing |
