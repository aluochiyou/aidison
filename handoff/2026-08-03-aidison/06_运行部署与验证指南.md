# 运行部署与验证指南

## 1. 当前运行环境

- 宿主：Windows；
- 容器：Docker Desktop；
- 后端：Python 3.11–3.12；
- 数据库：PostgreSQL 17；
- 前端：Node/Next.js；
- 浏览器入口：`http://localhost:3000`；
- API：`http://localhost:8000`；
- 当前 Compose 服务：`postgres`、`api`、`worker`、`web` 均 healthy；
- 当前运行库 migration：`2b7c4d8e1f03`。

## 2. 环境变量

只在系统环境或未提交的本机 `.env` 中配置值，不把值写入仓库、聊天、日志、Artifact 或交接文档。

主要变量名：`DEEPSEEK_API_KEY`、`TAVILY_API_KEY`、`GITHUB_API_KEY`、`DATABASE_URL`、`TEST_DATABASE_URL`。

DeepSeek、Tavily 和 GitHub Key 已完成本机配置；接手时只检查是否存在，不输出值。Aidison 当前不提供 OpenAI provider 路径。

## 3. 启动和只读检查

```powershell
cd D:\agent_project\codex\aidison
docker compose ps
docker compose logs --tail 100 api worker web
```

需要重建时才运行：

```powershell
docker compose build
docker compose up -d
```

这会改变当前容器状态。恢复开发前应先确认未提交源码与镜像内容一致。

## 5. 测试数据库安全边界

集成测试会执行 `TRUNCATE ... CASCADE`，禁止连接 `localhost:5432/aidison`。

长期 `127.0.0.1:55432/aidison_test` 含一条早期定义不同的 `research-worker-ro@4`，immutable gate 会拒绝覆盖。最可靠的回归方式是创建无卷临时 PostgreSQL 17，并让 `DATABASE_URL` 和 `TEST_DATABASE_URL` 指向该可丢弃库。

若两个 DSN 相同，即使数据库可丢弃，也需要显式：

```powershell
$env:AIDISON_ALLOW_SHARED_TEST_DATABASE='1'
```

这个变量只用于已确认可丢弃的测试容器，不能用来绕过运行库保护。

## 7. Live 验证的准确状态

### 已成功的单项

- Tavily Remote MCP 返回 PX4 官方来源；
- MAVSDK 网页形成 Artifact/hash/EvidenceBinding；
- GitHub 官方 MCP 读取公开 README 并形成 `github_snapshot`；
- 一次四旋翼 Research root + 两 child 完整成功并生成 Decision/Evidence/Candidate/Artifact。

### 未关闭的门

同一端到端 live pytest 重复执行时曾出现 child `worker_error`；最后一次 Docker 内尝试又遇到 GitHub DNS 的 `server misbehaving`，随后无 Key DNS probe 恢复。结论是外部闭环存在成功证据，但重复性仍为 failed/not stable。

不要通过增加无限重试、放宽预算或绕过 Artifact/EvidenceBinding 来“刷绿”该门。

## 8. 备份与恢复

操作说明见 `ops/README.md`。当前脚本要求先暂停 API/worker 写入，通过只读 Artifact Gate，再生成 PostgreSQL custom dump、Artifact snapshot 和 SHA-256 manifest，并且只恢复到新的 Compose project。

当前运行库有 5 条 `present` metadata，但 Artifact volume 中缺少对应字节，因此正式备份会按设计拒绝。不要绕过 Gate。

## 9. 停止服务

如果用户不需要继续展示，可以执行：

```powershell
docker compose stop
```

这会停止容器但保留 volume。当前交接过程没有替用户停止服务，也没有执行 `docker compose down` 或删除任何 volume。
